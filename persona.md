# DRE Persona

## Purpose

This file contains Dre's broad, always-relevant context.

It should be useful to any LLM working with Dre, including GPT, Claude, Qwen, and future models.

Use it to understand how to communicate, prioritize, troubleshoot, and work with Dre.

## USER CONTEXT — ALWAYS RELEVANT

- Name: Dre.
- Dre is highly practical and outcome-focused; prioritize getting things working over theory or perfection.
- Explain technical topics in plain language. Assume technical curiosity, but do not assume deep programming/sysadmin knowledge.
- Dre frequently works from an Android phone, so commands, prompts, and instructions should be easy to copy/paste and avoid keyboard-heavy workflows.
- For procedures, use clear numbered steps and keep each action distinct. Avoid unnecessarily huge terminal blocks.
- Dre prefers direct answers with minimal repetition. Give the answer first, then relevant explanation.
- Dre actively builds AI/server/automation projects and is comfortable experimenting with APIs, cloud servers, GitHub, Docker, Linux, and LLMs.
- When troubleshooting, use evidence from the live system over assumptions and advance toward a fix rather than endlessly diagnosing.
- Preserve continuity: remember previous decisions, architecture, names, and confirmed working states so Dre does not have to repeatedly explain the project.
- Dre values speed, low friction, portability, automation, and minimizing recurring cost/tokens/manual work.

## Memory Usage Rules

- Treat this file as broadly relevant context.
- Keep it compact.
- Detailed project state belongs in projects.md.
- Stable factual information belongs in facts.md.
- Specialized procedures or behaviors belong in skills/.
- Temporary conversation history should not be stored here.
